Ship Sentinel

Makes Claude run your pre-ship check skills before it pushes, publishes or deploys. A Claude Code mod that holds the command until the checks have run since your last edit.

/plugin install ship-sentinel --marketplace arm-pz/ship-sentinel

Run it inside Claude Code 2.1.287 or later, the release that added mods. Version 0.1.0, free under MIT. Fails open, and touches no files, network or processes.

Held until your checks have run.

Matched git push. In ask mode you choose “Run checks first” or “Ship anyway”.

Skills load when Claude decides

You wrote the checks as skills: a security pass, a performance audit, a preflight. Claude loads a skill when it decides to, and the moment you most want it to is the moment it is least likely to, with a push or a deploy a few seconds away.

Ship Sentinel holds git push, PR, publish and deploy commands until your check skills have run since your last edit. It contains no checks of its own; it makes sure yours ran.

ask
The default. The command waits and you choose “Run checks first” or “Ship anyway”. Shipping anyway lasts until the next edit.
block
The command is refused with an instruction for Claude: run the skills, fix what they find, then retry.
nudge
The command runs, and Claude is reminded which checks are still outstanding.

Two commands to set it up

Install the mod from its own marketplace, in Claude Code.

/plugin install ship-sentinel --marketplace arm-pz/ship-sentinel

Name your checks, for example pre-ship-security-red-team,pre-ship-performance-audit. All of them must have run since the last edit. Any skill name works; the default is release-gate.

/plugin configure ship-sentinel@ship-sentinel
  • From a shell, Claude Code 2.1.292 or later: claude plugin install ship-sentinel --marketplace arm-pz/ship-sentinel
  • For one session from a clone: claude --plugin-dir ./ship-sentinel, then /plugin lists it as active.

Questions before you install it

Does it run my checks?

No. It holds the command and tells Claude, or asks you, which skills to run first. In ask mode you decide; in block mode Claude is told to run them and retry.

Can Claude get around it?

Yes, and so can a rewritten command. It reads the text of a Bash command, so it is a reminder, not a security control, and echo "git push" also matches. For enforcement use permission rules or managed settings.

What can it touch?

Four calls: $.command.register, $.ui.ask, $.ui.status and $.ui.toast. No files, processes, network, environment variables or model calls. Mods are not sandboxed, so read that list, and the one short file, hooks/register.js, before installing any mod.

Does “ran” mean “passed”?

No. It means the skill was loaded since your last edit. A skill that was loaded and then ignored counts as run. Checking a receipt the skill writes is a planned improvement, described in DESIGN.md.

What if I only use claude -p or the VS Code panel?

Hooks run, but a question or toast may not draw, so use block mode there. Under an organisation that allows only managed mods, user mods do not load.

Does it work with subagents or MCP tools?

Not tested with subagents. It watches Bash commands only, so a ship done through an MCP tool is not seen.
