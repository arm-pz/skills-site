Diagnose Usage

Diagnoses why a Claude Code session or day burned through usage limits faster than expected, and says what to change.

3 files and 86 lines, free under MIT. Built from arm-pz/diagnose-usage at d8df948.

What it is for

Diagnoses why a Claude Code session or day burned through usage limits faster than expected, and says what to change. Reads the user's own /usage breakdown, checks the known heavy-session causes (high effort levels, subagents inheriting effort, goal mode, workflows, agent teams, long SDK jobs), and returns up to three ranked culprits with one fix each, plus when to send /feedback.

Reach for it when

  • The user says Claude Code usage is draining fast, they hit or are nearing their limit sooner than expected, one session cost far more than expected, or asks what /usage shows or how to cut burn in a session that already ran.

Not for

  • Choosing an effort level before work starts or using less going forward (use choose-effort)
  • For plan limits, prices and API billing (use product-self-knowledge)
