    What it checks.

    The same checks as check_skill.py, the open validator inside tune-skill. A test compares this page's code with that script on 1,342 skill folders, and they agree on every one.

    • Frontmatter parses. A strict YAML loader can read the block between the --- lines.
    • Name is valid. Present, lowercase words joined by hyphens, 64 characters or fewer, and the same as its folder.
    • Description fits. Present and within the 1,024-character limit, with a warning from 950.
    • Description says when. It has "Use when" wording, so the agent knows which requests it answers.
    • Description says when not. It has a "Not for" boundary, so it stays out of its neighbours' way.
    • Heading matches the name. A different H1 is often a leftover from a rename.
    • Body is a sensible length. Over 500 lines, detail belongs in references/.
    • Referenced files exist. Every references/, scripts/, examples/ and assets/ path the body names is in the folder. GitHub links only.
    • Counts are true. If the body says "six steps", some list or table in it has six entries.
    • Timing is honest. A note when the skill says it must run before a push or deploy, which a description alone cannot guarantee.

    Before you paste.

    Where does my SKILL.md go?

    Nowhere. The check is a script that runs in this page, and pasted text is never sent to us or stored. If you give a GitHub link, your browser asks GitHub's public API for the file directly. You can read the script at /check/check-core.js.

    Does a clean result mean my skill will trigger?

    No. It means nothing in the file's shape is stopping it. Whether an agent picks your skill for the right request depends on what the description says and on the other skills installed beside it, and no script can judge that. Test it on real requests.

    I got warnings. Do I have to fix them all?

    No. Fix every FAIL. A WARN is a question to answer: a skill with no neighbours does not need a "Not for" line, and a heading that differs from the name on purpose is fine.

    What exactly do I get for $29?

    One email with three things: your SKILL.md as a replacement file, a list of findings that each quote the line and give the smallest fix, and a short set of test requests that should and should not trigger the skill. We tell you which checks we ran and which we could not.

    What is the refund policy?

    If the audit finds nothing worth changing, we refund the full amount without being asked. If you are unhappy with what you get back, reply within 14 days and we refund you. Refunds go back to the original payment method.

    Can you tune a private skill?

    Yes. Paste the file into your order email with anything sensitive removed. We read it to do the work and do not publish or reuse it. We never need access to your repo, your systems or your API keys.
